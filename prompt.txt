The fix, already designed and partially implemented, is documented in:

READ THAT FILE IN FULL BEFORE DOING ANYTHING ELSE. It is the actual spec --
this prompt only summarizes it and tells you what's left to do. If anything

resolve it in the direction of "smaller, cheaper, more defensible" -- there
is a hard deadline (see below).

Short version of the idea: the project's own VLM-benchmarking code already
excludes `panel_count` questions from scoring with the comment "the VLM
can't see the whole figure" -- i.e. every existing VLM in this benchmark can
only ever look at ONE panel crop at a time. The new contribution is (a) a
task that requires reasoning across MULTIPLE panels of the same compound
figure (which no single-panel VLM can do by construction), and (b) a tiny,
cheap, novel method -- a permutation-aware panel-set attention head trained
on top of already-cached, frozen CLIP/BiomedCLIP embeddings -- that solves
it. This is the paper's algorithmic novelty claim.

### 11.3 -- Panel-set attention model + training (spec section 4)

New script: `11_compositional_panel_vqa/03_train_panel_set_attention.py`

- Loads `compositional_vqa_dataset_{track}.parquet` plus the cached panel
  embeddings (`panel_image_embeds.npy` / `panel_image_ids.json` under
  `alignment_v1/embed_cache/` or `alignment_biomedclip_v1/embed_cache/`
  depending on track).
- Embed the (small, deduplicated) set of distinct question strings once
  using the SAME frozen backbone's text tower (transformers.CLIPModel for
  "clip", open_clip's BiomedCLIP loader for "biomedclip" -- see
  `05_pipeline_clip/stage2_clip_alignment.py` and
  `06_pipeline_biomedclip_ablation/stage2b_biomedclip_alignment.py` for
  the exact loading pattern to reuse). Cache to
  `compositional_vqa_v1/embed_cache/question_embeds_{track}.npy` +
  `question_texts_{track}.json`, restartable like the rest of the repo
  (skip-if-exists).
- Implement two model classes exactly per spec section 4 and section 5
  point 2:
    - `PanelSetAttention`: learned positional embedding (by reading-order
      index) added to each panel embedding, multi-head self-attention
      over the panel token set (with a padding mask for variable panel
      counts across a batch), then attention-weighted pooling against the
      question embedding, then a per-question-type linear classification
      head over that type's `answer_space`.
    - `MeanPoolAblation`: plain mean of raw panel embeddings, NO
      positional encoding, NO attention -- concatenated with the question
      embedding, then the same per-question-type MLP head shape. This is
      an ablation, keep it deliberately simple per the spec.
  Both models: multi-task (one shared trunk + separate small heads per
  question_type), trained jointly with cross-entropy summed/averaged
  across question types.
- Train/val/test split inherited from the dataset's own `split` column
  (never re-split here). Single seed = 42. No hyperparameter search --
  pick one reasonable small config (e.g. attention dim = embedding dim,
  1-2 heads, a couple hundred/thousand parameters in the MLP head) and
  say so plainly in the paper.
- CLI args: `--track {clip,biomedclip,both}` and `--mode {set_attention,
  mean_pool,both}`. Save each trained config's val/test accuracy (overall
  and per question_type) to
  `compositional_vqa_v1/metrics_{mode}_{track}.json`, and the checkpoint
  to `compositional_vqa_v1/model_{mode}_{track}.pt`.
- This should train in minutes even on CPU (inputs are small cached
  vectors, not images) -- if it's taking longer than that, something is
  wrong (e.g. accidentally re-embedding images), stop and check rather
  than letting it run for hours.
- Unit test with a synthetic dataset (a handful of fake panel-embedding
  sets + question embeddings + labels) verifying: the model trains
  without crashing, padding masking actually ignores padded panel slots
  (construct a case where changing a padded slot's values must not change
  the output), and both model classes produce differently-shaped
  attention behavior (mean-pool truly ignores position/order; set
  attention's output changes if you permute two real panels' order when
  positional embeddings are added -- this proves the positional encoding
  is doing something, don't skip this check).
