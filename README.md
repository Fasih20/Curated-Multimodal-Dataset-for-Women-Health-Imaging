# Women's Health Imaging ML — Dataset Pipeline

Builds a curated, leakage-safe dataset of medical-imaging figure panels
(captioning + VQA) from PMC open-access articles, using a YOLO-based
compound-figure panel detector and a CLIP-family alignment step, then
benchmarks 8 vision-language models against it.

## What's in here

| Stage | Folder | What it does |
|---|---|---|
| 1 | `01_data_acquisition/` | Inventory source files, build the PMCID train/val/test split manifest |
| 2 | `02_cleaning_dedup/` | Integrity checks, exact-duplicate resolution, compound-image flagging + policy |
| 3 | `03_medicat_yolo_prep/` | Convert MedICaT subfigure annotations into a YOLO-format training set |
| 4 | `04_yolo_training/` | Train + qualitatively check the panel detector |
| 5 | `05_pipeline_clip/` | Stage 0–8: main track — detect panels, align with CLIP, quality-filter, split, build retrieval/VQA/captioning datasets |
| 6 | `06_pipeline_biomedclip_ablation/` | Stage 2b–8b: same pipeline, BiomedCLIP instead of CLIP (ablation) |
| 7 | `07_comparison/` | Stage 9: head-to-head CLIP vs BiomedCLIP |
| 8 | `08_vlm_benchmarking/` | Stage 10a: benchmark Qwen2-VL-2B, BLIP, PaliGemma (Colab, 1 GPU) |
| — | `09_utils/` | Colab session backup/restore, zip+download — dev convenience, not part of the pipeline |
| — | `10_kaggle_models/` | Stage 10b: benchmark the other 6 VLMs — Qwen2-VL-7B, LLaVA-1.5-7B, InstructBLIP-Vicuna-7B, Idefics2-8B, Llama-3.2-11B-Vision, LLaVA-NeXT-13B (Kaggle, 2x T4) |

All 8 models are scored with the same `token_f1` / `exact_match` metrics
across both stages, so results are directly comparable in one table.

## Repo-committed data 

- `02_cleaning_dedup/data/compound_precision_review.csv` — the 200-sample
  manual precision review behind the compound-image detection policy
  (see `06_apply_compound_image_policy.py`).
- `figures/` — final report figures: compound-image handling +
  CLIP/BiomedCLIP alignment demos (`5588608__4246_demo.png`,
  `10289791__580_demo.png`, `10924917__692_demo.png`) and the
  CLIP-vs-BiomedCLIP `quality_overview.png`.

Everything else (`pipeline_data/`, model checkpoints, prediction parquets)
is regenerated by running the pipeline and is intentionally not committed
— see `.gitignore`.

## Requirements

- Python 3.10+
- A GPU for Stage 4 (YOLO training), Stage 2/2b (CLIP/BiomedCLIP alignment),
  and Stage 10 (VLM benchmarking). Everything else runs fine on CPU.
- Stages 1–9 were developed and run on **Google Colab** (a single GPU).
  Stage 10's remaining 6 models were run on **Kaggle** (2x T4, for model
  sharding across GPUs). Paths in the scripts still reflect that — see
  "Running this outside Colab/Kaggle" below.

```bash
pip install -r requirements.txt
```

## Running it

### On Colab (as originally developed)

The scripts under `01_data_acquisition/` through `08_vlm_benchmarking/`
use Colab paths (`/content/drive/MyDrive/...`, `/content/pipeline_data/...`)
as-is. Mount Drive, adjust `DRIVE_ROOT` at the top of
`01_data_acquisition/01_inventory_and_split_manifest.py` to point at your
copy of the source data, then either:

- run each script as a notebook cell in stage order (fastest way to
  reproduce exactly what was originally run), or
- `!python run_pipeline.py` from a Colab cell once paths are set, which
  runs every stage in order and stops on the first failure.

`run_pipeline.py --skip-optional` skips the analysis-only diagnostic
scripts (duplicate-spike diagnosis, compound-flag precision check, etc.)
for a faster, non-diagnostic run. `--track clip` skips the BiomedCLIP
ablation (Stage 2b–8b) if you only need the main track.

### On Kaggle (Stage 10, remaining 6 models)

Attach the `pipeline_data/` produced by Stage 5–8/8b as a Kaggle input
dataset, adjust `PIPELINE_ROOT` at the top of
`10_kaggle_models/01_benchmark_6_additional_vlms.py`, and run it in a
notebook with 2 GPUs enabled. It's restartable — interrupting and
re-running skips predictions already saved.

### Running this outside Colab/Kaggle

Every script still has hardcoded `/content/...` or `/kaggle/...` paths.
To run locally or in CI, either:
1. Edit the path constants at the top of each script (`DRIVE_ROOT`,
   `PIPELINE_ROOT`, `IN_PATH`/`OUT_PATH`, etc.) to point at your own
   filesystem, or
2. Ask for a refactor to a single shared `config.py` / environment
   variables — not done yet, flagged as a possible follow-up in
   `NOTES_FOR_AUTHOR.md`.

## Output

Running the full pipeline produces, per track (clip / biomedclip):
- a cleaned, deduplicated, panel-split image manifest
- a retrieval baseline (Stage 5), a VQA dataset (Stage 6), and a
  captioning dataset (Stage 7)
- a final summary JSON + `METHODOLOGY.md` (Stage 8/8b)

Then Stage 9 produces a CLIP-vs-BiomedCLIP comparison report, and
Stage 10 (split across `08_vlm_benchmarking/` + `10_kaggle_models/`)
produces per-model captioning/VQA metrics plus a combined
`combined_all_tracks_all_models.json` covering all 8 benchmarked models.
